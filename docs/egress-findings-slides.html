§1b Request type · 40 entities, two ways measured

Array read beats export 1.8×.

Export re-encodes an HDF5 container and ships every artifact. An array read ships the one you asked for, raw.

HDF5 export 188.6 204.2 ms/ent

Caveat

fields= selects entities, not artifacts, so the 86 ms gap mixes HDF5 encode with reading the entity's other artifacts. The 1.8× is real; the attribution inside it isn't settled.

Scaling · data size projected

Bytes per node set the rate.

rate ≈ bytes ÷ ( t_fixed + bytes ÷ B_eff )
t_fixed
Cost per node whatever its size: lookup, file open, HDF5 header, request overhead. ≈ 0.10 to 0.20 s, measured.
B_eff
Rate for the bytes themselves: storage read, encode, wire. The ceiling a large array approaches. Not yet measured.

GenericSpin · 10,000 entities

Array (200,)

1.6 KB/node. t_fixed swamps the payload. Full traversal ≈ 37 min.

RIXS · 7 entities

Array (651, 487)

2.54 MB/node, 1,585× more. t_fixed amortized. Only shape that nears the wire.

Small nodes scale with array size alone. Large nodes approach B_eff, where GB/s lives. Measuring B_eff locates the crossover at bytes ≈ t_fixed × B_eff.

Scaling · layout predicted, not yet measured on egress

Layout is the biggest untested lever.

It sets how many files the server opens per export, landing in app, which is 92% of wall.

per_entity

One file per entity → N opens, no cache reuse. Worst.

grouped

One file, one group each → one open, cache-warm.

batched

Stacked on axis-0 → best locality if the adapter slices lazily.
